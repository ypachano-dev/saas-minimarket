# Guías de Comportamiento (basadas en Andrej Karpathy)

> Fuente: [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills). Estas guías priorizan precaución sobre velocidad. Para tareas triviales, usa criterio.

## 1. Pensar antes de codear

**No asumas. No escondas la confusión. Expón los trade-offs.**

- Antes de implementar, declara tus suposiciones explícitamente. Si hay incertidumbre, pregunta.
- Si existen varias interpretaciones válidas, preséntalas — no elijas en silencio.
- Si existe un enfoque más simple, dilo. Cuestiona cuando corresponda.
- Si algo no está claro, detente. Nombra qué te confunde. Pregunta.

## 2. Simplicidad primero

**El código mínimo que resuelve el problema. Nada especulativo.**

- Sin features más allá de lo pedido.
- Sin abstracciones para código de un solo uso.
- Sin "flexibilidad" o "configurabilidad" que no se solicitó.
- Sin manejo de errores para escenarios imposibles.
- Si escribiste 200 líneas y podrían ser 50, reescríbelo.

Pregúntate: "¿Un ingeniero senior diría que esto está sobre-complicado?" Si la respuesta es sí, simplifica.

## 3. Cambios quirúrgicos

**Toca solo lo que debes. Limpia solo el desorden que tú generaste.**

- No "mejores" código, comentarios o formato adyacente que no pediste tocar.
- No refactorices lo que no está roto.
- Respeta el estilo existente, aunque lo harías distinto.
- Si notas código muerto no relacionado, menciónalo — no lo borres.
- Cuando tus cambios dejan huérfanos (imports/variables/funciones que ya no se usan por TU cambio), elimínalos. No elimines código muerto preexistente sin que se pida.

La prueba: cada línea cambiada debe trazarse directamente al pedido del usuario.

## 4. Ejecución dirigida por objetivos

**Define criterios de éxito. Itera hasta verificar.**

- "Agrega validación" → "Escribe pruebas para inputs inválidos, luego haz que pasen."
- "Arregla el bug" → "Escribe una prueba que lo reproduzca, luego haz que pase."
- "Refactoriza X" → "Asegura que las pruebas pasen antes y después."

Para tareas multi-paso, declara un plan breve:

```text
1. [Paso] → verificar: [chequeo]
2. [Paso] → verificar: [chequeo]
3. [Paso] → verificar: [chequeo]
```

Criterios de éxito fuertes permiten iterar de forma independiente. Criterios débiles ("que funcione") exigen aclaraciones constantes.

## Especificación del Sistema: 3Q Nexus ERP (SaaS Multi-Tenant)

### Estado Actual del Proyecto

- **Fase:** En producción activa de funcionalidades. No es un esqueleto: Caja/POS, CRM, Balanza Digital, Almacén, Cartera, Tesorería, Delivery, Visitas RTC, Consola SaaS Maestro y los agentes de IA (VALE, YHORGE, ALO) ya están construidos y operativos.
- **Stack:** Backend FastAPI + SQLAlchemy (`app/`); Frontend React + Vite + TypeScript + Tailwind (`frontend/`).
- **Base de Datos:** SQLite por defecto en desarrollo local (sin XAMPP); el modelo está pensado para migrar a MySQL en producción (`pymysql` ya está en `requirements.txt`).
- **Multi-tenant:** todo aislado por `empresa_id`. El sector del inquilino (`TipoNegocio`: Minimarket/Ferretería/Agropecuaria/FerreAgropecuaria) determina módulos activos y nomenclatura — ver `app/core/negocio_config.py`.
- **Migraciones:** no hay Alembic. Cada cambio de esquema es un script `migrate_*.py` en la raíz que se corre una vez a mano.

### Modelo de Datos Core: Ficha Técnica del Producto (Minimarket/Retail/Veterinaria)

Cada producto dentro del catálogo debe responder al aislamiento lógico por `empresa_id` y mapear los siguientes atributos obligatorios de forma estricta:

1. **Identificadores:** `codigo_interno` (Llave única compuesta con empresa_id), `codigo_barras`, `nombre`, `marca`, `linea` (Línea Crítica), `clase_o_tipo`.
2. **Logística:** `tipo_envase` (Saco, Blíster, Bandeja, Kg), `ubicacion` (Pasillo, Anaquel, Cava), `refrigerado` (Boolean), `perecedero` (Boolean).
3. **Control Temporal:** `fecha_elaboracion`, `fecha_vencimiento`, `fecha_ingreso_stock`.
4. **Inventario:** `stock_minimo` (Decimal para balanzas/KG).
5. **Financiero:** `costo_usd`, `precio_1_detalle`, `precio_2_mayorista`, `precio_3_especial`, `aplica_iva` (Boolean).
